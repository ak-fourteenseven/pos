# 餐飲 POS 系統點餐流程與業務邏輯設計 (基於實際菜單)

> 本文檔由實體菜單圖片提煉，已全部落地到系統實作中（套餐向導、配料階梯計價、飲品時段計價引擎、廚房單/收銀單雙視圖）。

## 1. 菜單結構分析與資料建模

根據實體菜單，系統資料結構需支援「套餐組合」與「單品」兩種模式。

### 1.1 核心分類 (Categories)
1.  **湯底 (Soup Base)**：單價 $35 (如：雲南酸辣、招牌酸麻辣、清湯等)。
2.  **麵類 (Noodles)**：預設 $0 (烏冬 +$2，芽菜底 $0)。
3.  **辣度 (Spiciness)**：屬性選項，非獨立計費項目 (清湯不適用)。
4.  **湯餃 (Dumplings)**：單價 $45 (淨湯餃10隻 / 湯餃上海麵)。
5.  **配料 (Toppings)**：分階梯計價 ($7, $8, $9, $11)。
6.  **飲品 (Drinks)**：跟餐價 ($7-$10)，受時段與冷熱屬性影響。
7.  **精美小食 (Snacks)**：獨立計價單品 ($16-$38)。

### 1.2 飲品計價規則引擎 (Pricing Engine)
飲品價格非固定，需根據「時段」與「冷熱屬性」動態計算：
*   **下午茶時段**：所有冷熱飲品均 **$0 (免費贈送)**。
*   **午市 / 晚市時段**：
    *   **熱飲**：**$0 (免費)**。
    *   **冷飲**：原價 **+ $3** (例如原價 $7 的凍奶茶，實收 $10)。

## 2. 點餐 UI 交互流程設計

POS 前台介面採用「向導式 (Wizard)」設計，引導店員快速完成點餐。

### 2.1 流程一：湯底套餐點餐 (主流程)
1.  **Step 1: 選擇湯底**（菜品網格中直接點擊，即為套餐基礎品項）
    *   6 種湯底 (雲南酸辣、招牌酸麻辣、四川麻辣、香濃沙嗲、清湯、熱拌)。
    *   *邏輯*：選擇「清湯」時，向導自動跳過「辣度」步驟。
2.  **Step 2: 選擇麵類**
    *   8 種麵類。選擇「烏冬」時，訂單總額自動 +$2。
3.  **Step 3: 選擇辣度**
    *   8 種辣度 (唔辣 至 勁辣)。若 Step 1 選清湯，則此步自動跳過。
4.  **Step 4: 選擇配料 (Toppings)**
    *   按價格分組展示 ($7/$8/$9/$11 配料)。多選，即時更新總價。
5.  **Step 5: 選擇飲品**
    *   提供「凍/熱」切換，系統自動抓取當前時間判斷時段計價。
    *   附加選項：口味勾選 (走甜/少甜/多甜/走冰/少冰/多冰)。

### 2.2 流程二：湯餃套餐點餐
1.  **Step 1: 選擇湯餃類型**：淨湯餃10隻 ($45) / 湯餃上海麵(6隻餃子) ($45)。
2.  **Step 2: 選擇餃子餡料**：韭菜餃 / 粟米餃 (必選單選)。
3.  **Step 3: 選擇飲品**：邏輯同「流程一 Step 5」。

### 2.3 流程三：單點小食
*   直接在「精美小食」分區點擊添加。
*   部分小食 (如麻辣牛柏葉、爽脆豬耳) 彈出辣度/口味選擇框 (小辣/中辣/大辣 或 滷水/麻辣/香辣)。

### 2.4 退出與取消規則
*   任何向導/彈窗（湯底套餐、湯餃套餐、小食口味、獨立飲品）皆可隨時退出，四種方式等效：
    *   底部「取消」按鈕
    *   右上角「✕」
    *   鍵盤 `ESC`
    *   點擊遮罩背景
*   **取消＝不點單**：未按「加入購物車」前結束向導，商品不會進入購物車、不會建立訂單，僅關閉視窗。
*   實作契約：子元件需回傳 `update:modelValue`（設為 `null`）並觸發 `close` 事件，父層 `PosView` 據此清空 `wizardProduct` / `drinkProduct`，否則彈窗將卡住無法關閉。
*   重新點擊同一商品會重新初始化向導（回到 Step 1、預設選項與數量 1）。

### 2.5 主流程：點餐 → 下單送廚 → 結賬

POS 的核心時序改為「先送廚、後收款」，對應真實餐廳動線：

```
點餐（購物車）  →  🥘 下單（送廚房）  →  顧客用餐  →  💰 結賬
   未送廚明細        標記 sent_at           可加菜         收款、出小票
                     訂單 status=ordered
                     桌台 status=preparing
```

*   **下單（送廚房）**：`POST /api/orders/:id/submit`
    *   把該訂單所有 `sent_at IS NULL` 的明細標記為已送廚（同一時刻批量）。
    *   訂單 `status` 由 `open` → `ordered`，記錄 `ordered_at`、`submit_count`。
    *   桌台由 `occupied`（點餐中）→ `preparing`（製作中）。
    *   回傳廚房單（後廚 / 水吧分區）；首次為「新單」，之後為「加菜追加」。
    *   快餐／外帶模式：若尚未建立訂單，前端會先 `POST /api/orders` 建單再送廚，因此快餐同樣可先下單再結賬。
*   **加菜（追加）**：送廚後仍可加菜，新明細為未送廚；再按一次「下單」只送新增部分，並在廚房單標註「加菜追加」。
*   **結賬**：`POST /api/orders/:id/pay`
    *   **前置條件**：訂單至少有一筆已送廚明細，否則回 `請先下單送廚房，顧客用餐後再結賬`（前端「結賬」按鈕同步禁用）。
    *   結賬後桌台 → `cleaning`（待清），由桌台視圖「清台完成」恢復空閒。
*   **未送廚的購物車只是暫存**：未按「下單」前，購物車內容只在本地／進行中訂單內，不會進廚房；「下單」才是正式送廚。

### 2.6 訂單狀態機

| 狀態 | 意義 | 可執行動作 |
| --- | --- | --- |
| `open` | 已開台／已建單，尚未送廚 | 加菜、改數量、退菜、下單 |
| `ordered` | 已送廚（廚房製作中） | 加菜、下單（追加）、結賬、店長退菜、換桌、併桌 |
| `completed` | 已結賬 | 查詢、報表統計 |
| `voided` | 已作廢 | 查詢、報表統計 |

### 2.7 送廚後的修改限制

*   **改數量**：已送廚明細不可改數量（提示「請退菜後重新點」），避免廚房已備料。
*   **退菜**：未送廚明細任何人可退；**已送廚明細需店長權限**（`x-role=manager`），收銀員呼叫回 `403`，前端同步禁用按鈕。
*   **換桌 / 併桌**：`open` 與 `ordered` 訂單皆可換桌、併桌。

## 3. 購物車與訂單資料結構

購物車中的單一訂單項目 (Order Item) 採用嵌套結構，儲存於 `order_items.options`（JSON）：

```json
{
  "item_type": "combo",
  "product_name": "招牌酸麻辣",
  "price": 63,
  "quantity": 1,
  "options": {
    "base": "招牌酸麻辣",
    "noodle": { "name": "幼薯粉", "price_diff": 0 },
    "spiciness": { "name": "中辣", "price_diff": 0 },
    "toppings": [
      { "name": "肥牛", "price_diff": 11 },
      { "name": "炸魚蛋", "price_diff": 7 }
    ],
    "drink": {
      "product_id": 9,
      "name": "奶茶",
      "base_price": 7,
      "temperature": "COLD",
      "final_price": 10,
      "period": "晚市",
      "preferences": ["少甜", "走冰"]
    }
  }
}
```

> 價格由後端計價引擎覆核計算（`computeComboUnitPrice`），前端展示與後端落庫一致，防止改價。

## 4. 系統設定與時段管理

後台「系統設定 → 時段設定」可自訂三個時間段：
*   **午市**：11:00 - 15:00 (冷飲 +$3，熱飲免費)
*   **下午茶**：15:00 - 18:00 (冷熱全免)
*   **晚市**：18:00 - 23:00 (冷飲 +$3，熱飲免費)

### 4.1 前端即時計算邏輯

```javascript
// 實現：client/src/utils/pricing.js
function drinkPrice(basePrice, temperature, slot) {
  if (!slot) return basePrice;
  if (slot.drink_all_free) return 0;              // 下午茶全免
  if (temperature === 'HOT') return slot.drink_hot_free ? 0 : basePrice;
  return basePrice + slot.drink_cold_extra;       // 午晚市冷飲加價
}
```

**時段取得時機**：`PosView` 以 `computed` 由「時段設定 + 每 10 秒更新的時間戳」即時推導 `nowSlot`，
因此時段設定載入完成後立即生效、跨時段邊界自動切換（不可在 setup 階段一次性計算，否則開單初始
10 秒內會誤用原價，導致前端顯示金額與後端覆核金額不一致）。

## 4. 系統架構：單一前端 SPA（收銀台 + 後台）

前端為單一 Vue 應用（`client/`，埠號 **5173**），共用 `shared/` 層（`@shared` alias）。登入後進入首頁儀表板，再選擇功能入口：

| 入口 | 路徑 | 內容 | 權限 |
| --- | --- | --- | --- |
| 首頁 | `/` | 功能選擇儀表板 | 已登入 |
| 收銀台 | `/pos`、`/tables` | 收銀台、桌台視圖 | 店長／收銀員 |
| 後台管理 | `/admin/*` | 報表統計、菜品/桌台/員工/支付方式/門店資訊/時段設定、系統維護 | **僅店長**（路由守衛 + 首頁隱藏入口） |

*   收銀員直接訪問 `/admin/*` 會被導回首頁並提示僅限店長。
*   登入頁共用 `shared/views/LoginView.vue`，成功後導向首頁 `/`。
*   透過 `/api` 代理到服務端 3001，身份以 `x-user-id` / `x-role` 頭部傳遞。
*   共用層包含：`api.js`、`stores/{auth,catalog,businessDay,toast}`、`utils/{format,pricing}`、`components/Modal.vue`、`style.css`、`tailwind-preset.js`。
*   收銀台採 per-cashier **營業日**：首頁進入前開市（開市現金），日結後依支付方式彙總；訂單寫入 `business_date` / `business_day_id`。

## 5. 列印小票格式 (ESC/POS)

結帳完成後的小票彈窗提供雙視圖：

### 5.1 廚房單（後廚/水吧）
```text
【廚房單】POS20261016-0005 · 桌台 A1
【廚房】
1x 招牌酸麻辣
     麵: 幼薯粉
     辣度: 中辣
     加料: 肥牛, 炸魚蛋

【水吧】
1x 奶茶 (凍, 少甜, 走冰)
```

### 5.2 收銀單（顧客）
*   明細清晰：套餐基礎價、加料費分項列出。
*   優惠顯示：飲品免費時顯示「飲品時段優惠：原價 $7，優惠 −$7」，讓顧客感知到優惠。

> 實際硬體列印（ESC/POS 印表機、錢箱、客顯）需在桌面殼（Tauri/Electron）中接入本地外殼程式；當前版本提供完整的列印內容預覽。
